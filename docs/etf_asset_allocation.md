상세 근거·테스트 시나리오는 [검토 기록](etf_rebalance_review.md)에 있다.

## 현재 사용자 결정

- ETF 자산배분 계좌는 **account2**다.
- 매월 VAA·LAA·듀얼 모멘텀에서 정한 종목·비율은 그대로 사용한다.
- 이전 전량매도 지시는 2026-09-09 사용자 결정으로 **차액 재분배**로 대체했다.
  예: 10주를 보유하고 목표가 12주면 2주만 산다. 목표가 8주면 2주만 판다.
  목표에서 제외된 관리 ETF만 전량 매도한다.
- 미리보기 → 사용자 확인 → 주문 흐름을 유지한다. 자동 주문은 승인되지 않았다.
- account2 전체가 이 전략 소유라고 가정하지 않는다. 다른 전략 보유분은 제외한다.

## 구현과 실제 연결을 구분할 것

`trading/allocation_rebalance.py`는 차액 계산, 영속 주문 기록, 중복 전송 방지,
매도 체결 대조 후 실제 현금을 다시 조회하는 흐름을 구현했다. 모의 broker로 검증했다.
하지만 `web/asset_allocation_api.py`의 실제 팩토리는 아직 `UnavailableBroker`다.
따라서 **실주문 기능이 완성된 상태가 아니다**. 환경변수만 켜거나 UI 경고를 지워서 해결하면 안 된다.

연결 완료에 필요한 근거:

1. 키움 미국주식 미체결·주문체결 내역 API의 요청/응답, 전체 페이지, 거래일·계좌 범위.
2. 주문번호 또는 고유 조건으로 원래 주문과 대조. 타임아웃은 접수 여부 불명으로 유지.
3. USD 주문가능 현금의 미체결 예약금·수수료 반영 의미. 이미 반영한 예약금을 다시 빼지 않는다.
4. 시세 원시각 해석과 60초 유효성 검사. 조회한 현재 시간을 시세 시각으로 대신하지 않는다.
5. 계좌 내 전략 소유범위. 같은 ETF에 다른 전략 수량이 섞이면 별도 수량 원장이 필요하다.

## 설정

- `ALLOCATION_LIQUIDATION_SCOPE`: 이름은 호환 유지. 의미는 전량매도 목록이 아니라
  이 전략이 전용 소유한 관리 ETF 목록. 이전 달 보유 ETF도 포함해야 한다. 임의로 계좌 전체를 넣지 않는다.
- `ALLOCATION_JOURNAL_PATH`: 모든 worker가 공유하는 영속 로컬 SQLite 절대 경로.
  삭제하거나 임시 파일로 바꾸면 중복 방지 근거를 잃는다. 다중 호스트는 별도 설계가 필요하다.
- `ALLOCATION_RESERVE_BPS=100`: 매수 예산의 1%를 남기는 보수적 설정. 증권사 수수료율이라는 뜻이 아니다.
