# 종목별 섹터 표시와 섹터 최근 추세 (표시 전용)

2026-10-31 추가. 스캔 카드에 종목의 섹터와 그 섹터의 최근 추세(강한 상승·상승·횡보·하락·강한 하락)를
보여준다. **매수·매도·알림·Strict Gate 2 판정에는 쓰지 않는다.** 투자 전략 검증 결과가 아니라 표시
기능의 설계 기준이다.

## 섹터 분류 소스

- **미국 GICS(기존)**: 위키백과 S&P500 표의 GICS Sector → 기존 11개 SPDR ETF 대응표.
- **미국 보완 Yahoo**: GICS 가 없는 신호 종목(NASDAQ-100 의 외국 발행사, NYSE/NASDAQ 전체 유니버스)만
  `yfinance.Ticker.get_info()["sector"]` 를 명시적 대응표로 GICS 원문에 맞춘다. Yahoo(Morningstar) 분류는
  GICS 와 같지 않으므로 `sector_source=YAHOO` 로 구분하고 Gate 2 의 `sector_stage` 에는 넣지 않는다.
  대응표에 없는 이름은 미분류로 둔다.
- **국내 KRX-DESC**: `FinanceDataReader.StockListing("KRX-DESC")` 의 KSIC 업종(158종).
  - 현재 FDR 는 이 목록을 `fdr_krx_data_cache` GitHub CSV 에서 읽으며 컬럼이
    `Sector=KOSDAQ 소속부(벤처기업부 등, KOSPI 는 공란)`, `Industry=업종`, `Products=주요제품` 이다.
    (2026-10-30 CSV 와 설치된 FDR 의 실제 `StockListing` 호출로 확인: 2,690종목, 158업종, 소속부 값 없음)
  - FDR 의 KIND 직접 조회 경로는 `Sector=업종`, `Industry=주요제품` 이다. 로더는 `Products` 컬럼 유무로
    두 형식을 구분해 항상 업종을 고른다 (`sector_trends._kr_industry_column`).
  - KSIC 는 공식 업종 분류이지만 체감과 다를 수 있다. 예: 삼성전자 = `통신 및 방송 장비 제조업`.

## 섹터 성과와 추세 판정

- 지표: 최근 **20거래일 종가 수익률** `(마지막 종가 / 21번째 전 종가 − 1) × 100`.
- 5단계 (반올림 전 값으로 판정, `config.py`·`.env` 로 조정):

| 수익률 r | 추세 |
|---|---|
| r ≥ +5% | 강한 상승 `STRONG_UP` |
| +1% ≤ r < +5% | 상승 `UP` |
| −1% < r < +1% | 횡보 `FLAT` |
| −5% < r ≤ −1% | 하락 `DOWN` |
| r ≤ −5% | 강한 하락 `STRONG_DOWN` |

- 미국 성과: 해당 SPDR 섹터 ETF 의 종가(yfinance `auto_adjust=True`). 섹터 전체 수익률의 대용치다.
- 국내 성과: **이번 스캔 유니버스에서 같은 업종 종목들의 20거래일 수익률 중앙값**. 스캔이 이미 받은
  종가만 쓰므로 추가 가격 조회가 없다. KSIC 업종은 종목 수가 적은 곳이 많아 테마성 급등주 하나가
  평균을 뒤집지 않도록 평균 대신 중앙값을 쓴다. 공식 업종지수가 아니므로 화면에 표본 수를 함께 보인다.
  유니버스(KOSPI/KOSDAQ 선택, 시총·가격 필터)에 따라 값이 달라진다.

## 갱신 주기

| 대상 | 주기 |
|---|---|
| 국내 업종 분류 | 프로세스 캐시 24시간, 조회 실패는 1시간 기억 후 재시도 |
| Yahoo 보완 분류 | 종목별 7일, 실패·대응 없음은 1시간 |
| 미국 ETF 성과 | 스캔 시작 때 계산한 `get_market_stages()` 스냅샷(기존 60분 캐시). 스캔 중에는 재조회하지 않음 |
| 국내 업종 성과 | 매 KR 스캔(정규 16:10 KST, 수동 스캔) 종료 직후 계산 |
| 저장값 | 스캔 시점 스냅샷. API 조회 때 다시 계산하지 않음. 재검출된 신호는 다음 스캔에서 갱신 |

국내는 기존 저장·알림 순서를 바꾸지 않는다. 스캔 중 저장할 때는 업종명만 싣고, 스캔이 끝난 뒤
`_apply_kr_sector_trends` 가 이번 스캔에 저장·갱신된 KR 행(`scan_time ≥ 시작 시각`)에 추세를 채운다.
재검출로 다시 저장할 때 추세 값이 없으면 이전 추세를 지우지 않는다. 따라서 KR 알림 메시지에는 섹터
추세가 들어가지 않는다.

## 데이터 누락 처리

어떤 경우에도 결측을 횡보로 대체하거나 값을 채워 넣지 않는다.

| 상태 | 조건 | 화면 |
|---|---|---|
| 섹터 NULL | 분류 소스에 없음, 공급자 실패, 기능 도입 전 행 | `섹터 미분류` |
| 추세 NULL | 분류는 있으나 아직 계산 전(국내 스캔 진행 중, 이전 행) | `추세 집계 전` |
| `INSUFFICIENT` | 종가 21개 미만, 최근 21거래일 구간 안의 결측·이상값 / 국내 유효 표본 3종목 미만 또는 업종 내 70% 미만 | `추세 표본 부족` |
| `STALE` | 마지막 봉이 스캔일보다 7일 넘게 오래됨 | `추세 지연` |
| `UNAVAILABLE` | ETF 성과 없음, 국내 가격이 하나도 없음 | `추세 미확인` |

종가 정리: 같은 날짜는 마지막 값을 쓰고, 날짜순으로 정렬한 뒤 미래 날짜를 버린다. 그다음 **최근
21개 거래일 구간을 먼저 고정**한다. 그 구간 안에 숫자가 아니거나 0 이하·무한대인 종가가 하나라도
있으면 `INSUFFICIENT` 로 둔다. 결측을 지우고 더 오래된 가격으로 시작일을 당기면 실제 20거래일이 아닌
기간의 수익률이 정상값처럼 보이므로 그렇게 하지 않는다. 구간 밖의 결측은 판정에 영향이 없다.
가격 어댑터(`get_us_ohlcv`·`get_kr_ohlcv`)는 매매 판정용으로 결측 행을 `dropna` 한 표를 그대로
돌려주고, dropna 이전 종가의 최근 64개를 `df.attrs["raw_close_tail"]` 에 함께 싣는다. 추세는 이 원본
종가로 판정하므로, 공급자 응답의 종가 결측 행이 지워져 구간이 과거로 늘어나지 않는다. 거래량 등 다른
컬럼만 비어 지워진 행은 원본 종가가 있어 정상 판정한다. 이 값이 없는 표(다른 공급자, 테스트용 표)는
`Close` 를 쓴다.
공급자가 날짜 행 자체를 빠뜨리면 원본 종가로도 알 수 없다. 그래서 같은 달력끼리 구간을 맞춰 본다.
미국은 섹터 ETF와 SPY·QQQ 지수 중 가장 흔한 (시작일, 종료일)과 다른 섹터 ETF를 `INSUFFICIENT` 로 둔다
(판정 가능한 시리즈가 3개 미만이면 비교하지 않음).
국내 집계는 시작일·종료일이 모두 유니버스 기준 구간(최신 종료일, 그 종료일 종목들의 가장 흔한
시작일)과 같은 종목만 표본으로 쓴다. 거래정지 등으로 행이 빠져 구간이 다른 종목은 제외된다. 분모에는
가격 조회에 실패한 같은 업종 종목도 포함한다.

## 저장 (`scan_results`, Alembic `d4e8a17c5b92`)

`sector_source`(GICS/YAHOO/KRX), `sector_trend`, `sector_return_20d`, `sector_trend_asof`,
`sector_trend_basis`(`ETF:XLK` / `KR_SCAN_MEDIAN`), `sector_trend_sample`, `sector_trend_members`.
모두 nullable 이며 기존 행은 NULL 로 남는다. 앱 시작 경로의 `init_db()` 가 `alembic upgrade head` 를
실행한다. `/api/results` 는 이 값과 판정 기준 문자열(`sector_trend_rule`, 설정값으로 생성)을 돌려준다.
스캐너 조회 MCP(`/api/scanner-read`) 응답 필드는 이번에 바꾸지 않았다.

## 화면

카드의 종목코드 아래 한 줄: `[섹터명] [▲ 상승 +2.1%]`. 색은 화면의 기존 손익 표시(상승 녹색·하락 빨강)를
따르고, 판정하지 못한 상태는 점선 테두리로 횡보와 구분한다. tooltip 에 분류 출처, 성과 기준(ETF 또는
국내 표본 n/N), 기준일, 판정 기준을 보인다.

## 검증 범위와 한계

- 가짜 공급자와 임시 SQLite 로 판정 경계, 결측·중복·미래·오래된 가격, 국내 표본·커버리지·날짜 정렬,
  캐시 TTL, 스캔 저장·재저장·KR 후처리, Gate 2 불변, API 응답을 검증한다. 테스트는 섹터 공급자를
  기본 차단한다(`tests/conftest.py`).
- 실제 KRX-DESC 는 이 저장소의 로더로 조회해 업종 컬럼 선택을 확인했다. Yahoo `get_info` 와 실제 ETF
  시세는 이 작업 환경에서 호출 제한(HTTP 429)으로 확인하지 못했다.
- 운영 PostgreSQL 마이그레이션, 실제 스캔 결과의 업종별 표본 분포는 확인하지 않았다.
- 장중 수동 스캔은 미완료 당일 봉을 포함할 수 있다.
