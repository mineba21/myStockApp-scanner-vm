# B — 전체 보유 관측 및 shadow 비교

기준 d3f83a5, 사용자 요청 ‘B단계 진행’. 기존 전략·알림 선정·직접 발송은 유지한다.
이번 구현은 로컬 검증까지이며 운영 활성화/배포 및 C 발송 전환은 포함하지 않는다.

## 변경 계약

- `_check_holdings`에 선택적 관측 수집기를 전달한다. 반환 알림 목록과 기존 저장 값을 바꾸지 않는다. OFF면 수집기 생성·추가 쿼리가 없다.
- 수집기는 평가 전 보유항목 입력과 알림 상태를 복사한다. 전체 HOLD/억제/경고/실패 결과와 실제 마지막 일봉 라벨, 시세·벤치마크 가용성, 기존 선정 결과를 기록한다. 봉 확정은 UNKNOWN으로 남긴다.
- 같은 기존 `_holding_alert_due` 정책 함수에 복사된 이전 상태를 넣어 예상 결과를 비교한다. Weinstein 전략을 재실행하거나 복제하지 않는다. 손절 미등록의 개별 due와 묶음 포함 여부는 구분한다.
- 거래 일지를 정렬해 마지막 청산 후 재매수 거래를 에피소드 근거로 쓴다. 거래가 없는 수동 보유는 Holding 생성시점과 관측된 비활성 구간으로 구분한다. 관측 사이의 기록 없는 청산·재진입은 알 수 없다.
- 스캔별 예상 관측 ID 목록을 신규 `agent_scan_captures` 테이블에 먼저 커밋한다. 원 스캔 DONE 커밋 뒤 별도 세션으로 관측을 저장하고 완료 표시한다. 이 테이블 하나의 additive migration을 추가한다.
- 원 스캔 커밋과 관측 저장 사이의 종료는 누락 가능성이 있다. manifest도 실패하면 로그만 남고 완전한 탐지를 보장하지 않는다. 기존 Holding에서 사라진 중간 판정을 재구성하지 않는다.
- 영속 관측은 스캔 시작 ID/개정 순서로 재생하고 데이터 시점의 역행은 거절한다(A의 커서 계약 유지). 늦게 도착한 과거 관측은 감사 자료로 보존한다. 단순 scan ID 빈 번호는 gap이 아니다.
- 미완료 앞선 capture는 뒤 관측 처리에 장벽이다. 알려진 누락은 DEGRADED로 표시한다. 복구 가능한 관측은 재시도하고, 원본 없는 누락은 명시적 사유를 가진 기준선 재설정으로만 건너뛴다. 누락 이력은 보존하고 다음 이벤트에 gap 원인을 붙인다.
- 기존 스캔 완료 시 재생을 시도한다. 별도 CLI로 재생/현황/명시적 gap 해제를 제공한다. 자동 타이머·웹·scheduler 변경은 없다.
- B 수집기는 delivery 설정과 무관하게 shadow 저장소를 강제한다. 전달 대상과 발송 작업을 만들지 않는다.
- 전략 소스 및 사용 설정 버전, 보유 입력 버전 변경은 BASELINE_RESET 원인으로 기록한다. 상태 변화와 품질 변화는 분리하며 장애 중 마지막 유효 판단을 보존한다.

## 검증

기존 OFF 회귀와 ON/OFF 결과 동일성, 전체 관측, 선정 비교, 초기/악화/회복/왕복,
계좌/재진입/입력 변경, 데이터 장애·복구, 중복·역순·동시 처리,
중간 저장 실패·재생 재개·누락과 명시적 재설정, delivery 0건,
SQLite/PostgreSQL migration과 전체 회귀를 검증한다. 관찰 자료가 아직 없으므로 2주 shadow 운영의 유용성 판단은 후속이다.
