# account1 미국 Scanner 자동매수 ↔ S01 자동손절 연동 설계 (검토안 v2)

| 버전 | 날짜 | 변경 |
|---|---|---|
| v1 | 2026-11-25 | 최초 검토안 (P0~P6 백테스트와 함께) |
| v2 | 2026-11-25 | P7 결과 반영: 위험 예산(Entry/Current Heat 분리·미체결 예약·손절선 이탈·손절가 없는 보유), 계좌 공통 잠금과 주문 위험 예약, API 호출량 공유와 자동손절 우선, SHADOW/LIVE 완전 분리, A1~A8 상세화와 신규 A9~A12 |

**설계 검토 문서**이며 코드·운영 VM·저널·Migration 은 바꾸지 않았다. 실제 주문 취소 권한과 자동매수 정책은 승인되지 않았다.
자동매수 구현, SHADOW 운영, LIVE 활성화는 각각 별도 승인 대상이다.
근거 코드: `trading/auto_stop/{service,engine,store,settings,brokers}.py`, `trading/auto_stop/journal_migrations/ddl_v1.py`,
`trading/scanner_buy_orders.py`, `scanner/sizing.py`, `docs/auto_stop_sell.md`, `docs/scanner_buy_orders.md`.
SHADOW 구현 계획은 `AUTO_BUY_SHADOW_PLAN.md` 에 따로 있다.

## 1. 현재 구조에서 확인한 사실

| 항목 | 현재 | 자동매수 연동 시 영향 |
|---|---|---|
| 등록 경로 | `service.register` — 수동 연결(`source="MANUAL_LINK"`), 사람이 티커를 확인 입력 | 자동 경로 필요 |
| `source` CHECK | `'MANUAL_LINK','SCANNER_BUY','PROMOTED'` | **`SCANNER_BUY` 를 그대로 재사용** (스키마 변경 불필요) |

| 관리 수량 | `initial_managed_qty ≥ 1` 고정, 증가 경로 없음 | 부분 체결 증분용 **증가 전이** 필요 |
| 체결 반영 | 매도: `auto_stop_fill_ledger(order_id, cum_filled_qty)` PK 로 누적 증분만 반영 | 같은 패턴을 **매수 체결**에 적용 |

| account1 현황 (2026-11-25 조회) | 증권사 보유 평가액이 순자산의 약 28% (구체 금액·종목 수는 공개 저장소에 기록하지 않음). 손절가 등록 여부는 조회 MCP 범위 밖 | 4.1 의 "손절가 없는 보유" 정책이 **첫날부터 결정적** |

## 2. 목표 흐름 (첫 부분 체결부터 보호)

```
[스캔 마감 후]  불변 신호 스냅샷 → 적격 판정(제외 사유 기록) → 순위·Top-N → 결정 고정(BUY_DECIDED)
                 └ 계좌 잠금 아래에서 위험 예약(planned_risk = 주문수량 × (지정가 상한 − 고정 손절가))
[다음 정규장]    전송 직전 재검증(시장 상태·시세 유효성·매수 위치·손절가·R·현금·Heat) → 지정가 1회 전송
[30초 대조]      누적 체결 cum 증가 → buy_fill_ledger(order_id, cum) INSERT
                 └ 같은 트랜잭션: 포지션 없으면 생성(qty=delta) / 있으면 managed += delta, 예약 위험 → 체결 위험으로 이전
[S01 tick]       기존 손절 감시 그대로 (관리 수량 = 확인된 누적 체결 − 매도 수량)
[cutoff]         미체결 잔량 취소(승인 A3 필요) → 예약 해제. 추격 재주문 없음
```

### 2.1 결정 스냅샷 (불변)
- `auto_buy_decisions` (저널 전용 Migration `as0002` 로만 생성, 런타임 DDL 금지)
  - `snapshot_id`(→ `scanner_signal_snapshots`), `signal_key`, `ticker`, `signal_type`
  - **`stop_price` (결정 시점 Scanner 손절가, 불변)**, `pivot_price`, `decision_close`, `limit_cap`
  - `strategy_id`, `strategy_version`, `config_hash`, `rank`, `planned_qty`, `planned_risk_usd`,
    `equity_snapshot`, `entry_heat_snapshot`, `current_heat_snapshot`, `block_reason`(미선정 시)
  - `mode`, `virtual_account_id`(SHADOW), `decided_at`, `state`
  - UNIQUE(`mode`, `virtual_account_id`, `signal_key`) → 같은 신호 재주문 불가
- 스캔 DB(`scan_results`)는 재스캔으로 값이 바뀌므로 등록·손절 판단에 다시 읽지 않는다.

### 2.2 매수 주문
- LIVE 는 기존 `scanner_buy_orders` 와 **같은 SQLite**(lease·유니크 인덱스 공유)에 두고 상태를 분리한다:
  `auto_buy_orders` 신규 표 또는 `scanner_buy_orders.origin='AUTO'` (승인 A4).
- 주문은 1회 전송한다. 지정가 = min(결정 종가 × 1.01, 전송 직전 시세 기준 상한). 미체결 잔량은 cutoff 에 취소하고 재주문하지 않는다.
- 전송 직전 재검증 (하나라도 실패하면 SKIPPED, 사유 기록):
  1. 시장 상태(전략이 BULL 조건이면 직전 확정 상태가 BULL)
  2. 시세 유효성 (`quote_max_age_sec`, 급변 `quote_jump_pct`)
  3. 매수 위치 (시세 > 고정 손절가, R 3~15%, 지정가 상한 이내)
  4. 수량 = 운영 `calculate_position(지정가 상한, 고정 손절가, 순자산, 매수가능현금 − 현금 하한, Entry Heat 위험 합계)`
  5. Current Heat 경고·차단, 손절선 이탈 보유, 손절가 없는 보유 정책 (4.1)
  6. 보유·대기 주문 종목 아님
- 결과 불명(UNKNOWN)은 재전송하지 않고 주문내역 증거로만 해제한다 (기존 원칙 유지).

### 2.3 체결 증분 → 관리 수량
- `auto_buy_fill_ledger(order_id, cum_filled_qty, applied_delta, fill_px, applied_at, evidence)`, PK `(order_id, cum_filled_qty)`.
- 대조할 때 증권사 누적 체결 `cum` 이 기존 최대 `cum0` 보다 크면 **한 트랜잭션에서** 다음을 처리한다.
  1. ledger INSERT. PK 충돌이면 이미 반영된 것이므로 아무것도 하지 않는다 (멱등).
  2. 포지션이 없으면 `auto_stop_positions` 에 INSERT 한다.
     `source='SCANNER_BUY'`, `source_ref='auto_buy:{mode}:{order_id}'`, `stop_price` 는 결정 스냅샷 값, `initial_managed_qty=delta`.
  3. 포지션이 있으면 `remaining_managed_qty += delta`, `details.buy_cum_filled = cum`, 평단을 갱신한다.
  4. 위험 원장: 예약 위험에서 `delta × (지정가 상한 − 손절가)` 를 빼고, 체결 위험에 `delta × (체결가 − 손절가)` 를 더한다.
- `cum < cum0` (감소) → 매수와 포지션 모두 NEEDS_REVIEW, 신규 자동매수 중지, URGENT.
- 첫 체결분부터 손절 감시 대상이 된다. 전량 체결을 기다렸다가 등록할 때 생기는 감시 공백이 없다.

## 4. 운영 정책

### 4.1 위험 예산 (P7 결과 반영)

**두 가지 Heat 를 분리한다.** 둘 다 같은 시점의 계좌 순자산(현금 + 평가금액) 대비 비율이다.

| | 정의 | 용도 |
|---|---|---|
| **Entry Heat** | Σ(확정 체결가 − 고정 S01 손절가) × 남은 보유수량 + Σ 미체결 매수 (지정가 상한 − 손절가) × 주문 잔량 | **신규 자동매수 위험 예산** (`calculate_position` 의 open_risk 로 전달) |
| **Current Heat** | Σ max(현재가 − 고정 손절가, 0) × 남은 보유수량 + 미체결 예약 | 현재 평가 대비 손절 위험·집중도 **경고**. 차단 한도는 승인 A10 |

P7 근거 ($50k, 2021~2026, 운영형 UNL = 기간 제한 없는 S01):
- 운영 방식(현재가 Heat)으로 예산을 판단하면, 6년간 신규 매수가 12~17건으로 사실상 멈춘다. 평균 Current Heat 의 79~86% 가 손절 위험이 아니라 **평가이익**이었다.
- Entry Heat 로 바꾸면 거래가 167~231건으로 회복된다. 하지만 기간 제한이 없어서 손절되지 않은 포지션이 Entry Heat 를 계속 차지한다. 그 결과 Entry Heat 평균이 한도에 붙고(균형형 4% 한도에서 평균 3.5~3.9%), 미청산 자금 비중이 55~100%, 최대 섹터 비중이 21~76% 까지 올라간다.
- Current Heat 10% 차단을 더하면 UNL 거래가 195건에서 47건으로 다시 줄어든다. 15~20% 차단도 70~106건이다. 그래서 **Current Heat 는 경고로 쓰고, 차단 한도는 충분히 높게** 두는 것을 권장한다 (A10).
- 종목 비중 상한(10/15/20%)은 결과에 거의 영향이 없다. Heat 가 먼저 묶이기 때문이다. 현금 하한 20% 는 UNL 에서만 작동한다.

**미체결 주문 예약:** 결정 시점에 `qty × (지정가 상한 − 손절가)` 를 예약한다. 체결 증분마다 실제 체결가 기준 위험으로 옮기고, 취소·만료되면 해제한다. 예약은 계좌 잠금(4.2) 아래에서만 바꾼다.

**손절선 이탈 미청산 (현재가 ≤ 고정 손절가인데 아직 보유):**
- 위험이 해소된 것으로 보지 않는다. 운영 `calculate_open_risk` 는 0 으로 처리하지만, 자동매수 판단에서는 다르게 다룬다.
  - Entry Heat 에는 원래 위험을 그대로 둔다.
  - Current Heat 에는 max(진입가 − 손절가, 진입가 − 현재가) × 수량으로 계산한다. 이미 손절가 아래이므로 더 큰 쪽을 쓴다.
- 상태 `STOP_BREACHED_OPEN` 으로 따로 표시한다. 해소될 때까지 **신규 자동매수를 전부 차단**하고 URGENT 를 보낸다.
- 일봉 백테스트에서는 저가가 손절가 이하이면 그날 청산되므로 이 상태가 거의 생기지 않는다. 실제로는 매도 실패, 거래정지, 갭, 장외 시간에 생긴다.

**손절가 없는 기존 수동 보유 (위험을 0 으로 보지 않는다):**
- P7 스트레스 결과: 순자산의 30% 를 손절가 없이 보유한 상태에서 그 위험을 평가금액 × 15%(MAX_R 가정)로 Entry Heat 에 합치면 4.5% 가 된다. 균형형 한도 4% 를 넘으므로 **자동매수가 0건**이 된다. 전액(100%)을 위험으로 보면 38% 다.
- 실제 account1 은 2026-11-25 기준 보유 평가액이 순자산의 약 28% 다. 그대로 합치면 자동매수가 시작되지 않는다.
- **권장 정책 (승인 A6):**
  1. 자동매수 위험 예산은 **자동매수 포지션만의 Entry Heat** 로 판단한다 (자동매수 sleeve).
  2. 별도로 **계좌 전체 위험 한도**를 둔다: 자동 Entry Heat + Σ(S01 등록 수동 보유의 Entry 위험) + Σ(손절가 없는 보유 평가금액 × 가정 위험률) ≤ 계좌 한도. 이 한도를 넘으면 신규 자동매수를 차단한다.
     - 가정 위험률은 15% 를 제안한다. 백테스트·운영의 `MAX_R_PCT` 와 같은 값이며, 15% 넘게 손절폭이 벌어진 신규 매수는 애초에 하지 않는다는 기준과 맞춘다.
     - 계좌 한도는 10% 를 제안한다. 자동 4% + 수동 약 4.2%(28% × 15%) + 여유분이다.
  3. 손절가 없는 보유는 매일 보고서에 "위험 미확정" 으로 따로 표시한다. 그 평가금액은 **자동매수 가용 자금에서 제외**한다.
  4. 손절가 없는 보유가 계좌의 50% 를 넘거나 손절선 이탈 보유가 있으면 자동매수를 중지한다.
- 이 정책은 백테스트의 SPY 대리 스트레스로만 확인했다. 실제 수동 보유의 변동성·상관은 반영되지 않았다.

**자금 배분 (승인 A8):**
- 자동매수 sleeve 상한 = min(설정 비율 × 순자산, 순자산 − 수동 보유 평가금액 − 현금 하한).
- P7 의 UNL 에서는 미청산 자금 비중이 80~100% 까지 올라갔다. 자동매수 sleeve 상한(예: 순자산의 50%)과 섹터 비중 상한(예: 30%)을 제안한다. 단, 두 상한은 **백테스트로 최적화하지 않은 안전장치 제안**이며, SHADOW 에서 차단 빈도를 관찰한다.

### 4.2 계좌 공통 잠금과 주문 위험 예약
- 매수 엔진과 S01 tick 은 **같은 lease** 를 사용한다. 증권사 호출과 저널 쓰기는 한 작업자만 한다.
- 계좌 단위 상태 `account_risk_state(mode, account)` — 위험 예약, 현금 예약, 마지막 잔고 대조 시각.
  매수 결정·전송·체결 반영·취소는 모두 이 행을 조건부 갱신으로 바꾼다 (낙관적 버전).
- 같은 종목에 "매수 SENDING/UNKNOWN" 이면 손절 신규 매도 금지, "매도 SENDING/UNKNOWN" 이면 매수 대조 외 신규 동작 금지.
- 수동 주문(사이트의 스캐너 매수 확인 주문 포함)도 같은 SQLite 의 예약을 읽는다. 자동·수동 매수가 같은 현금을 두 번 쓰지 않게 한다.
- 증권사 주문내역에서 우리 것이 아닌 주문이 보이면 기존처럼 NEEDS_REVIEW 로 둔다.

### 4.3 매수 잔량 미체결 중 손절가 도달
1. 손절 트리거 → 매수 잔량 **취소 요청**. 취소가 확정되기 전에는 매도를 전송하지 않는다.
2. 취소 확정과 최종 누적 체결 확인 → ledger 에 반영한다.
3. 관리 수량 = 최종 누적 체결 → 기존 S01 매도 절차를 탄다.
4. 취소 결과가 불명이면 매도를 보류하고 URGENT, 사람 확인을 요청한다 (재시도 없음).
- AGENTS.md 예외는 **손절 매도의 취소·재주문**만 허용한다. 매수 자동 취소는 **새 승인이 필요하며 아직 승인되지 않았다** (A3).

### 4.4 감시 공백 최소화
- 체결 대조 주기는 30초(현재 S01 주문 상태 주기와 같음)이고, 체결 증분은 같은 트랜잭션에서 포지션에 반영한다.
- 대조 실패가 N회 연속되면 신규 자동매수 중지와 URGENT.
- 백테스트에서 같은 봉 손절은 보수(즉시 감시)와 대안(다음 날부터) 가정으로 계산했다. 차이는 0.1% 수준이었다.

### 4.5 실패 시 차단
- 포지션 생성·증분 반영 실패 → 해당 매수 NEEDS_REVIEW, **신규 자동매수 전체 중지**, URGENT.
- 다음 중 하나라도 해당하면 **신규 LIVE 자동매수를 차단**한다.
  - `AUTO_STOP_US_MODE != LIVE`
  - LIVE 게이트 미충족
  - S01 최근 tick 성공이 N분 이상 지연
  - S01 하트비트 실패
  - lease 이상
  - S01 연속 오류 보류 중
  - 429 증가
- 비상 중지(STOP)는 매수와 매도에 공통으로 적용한다.

### 4.6 SHADOW / LIVE 완전 분리
- 모든 신규 표에 `mode` 를 둔다. 유일 인덱스에 `mode` 를 포함한다. SHADOW 에는 `virtual_account_id` 를 추가한다.
- SHADOW 매수는 **주문 모듈을 import 하지 않는** 가상 브로커로만 체결한다. LIVE 포지션으로 복사하지 않는다.
- SHADOW 자동매수 포지션은 **SHADOW S01(가상)** 과만 짝을 짓는다. 현재 VM 에서 운영 중인 S01 SHADOW 저널에는 쓰지 않는다. 별도 저널 파일 또는 별도 mode 값을 쓰며, 이는 승인 A12 다.

### 4.7 기존 보유 종목
- account1 에 이미 보유(수동 포함)·S01 등록·주문 대기 중인 종목은 **자동매수하지 않는다** (추가매수 금지).
- 잔고는 매일 complete=True 로 확인한다. 불완전 잔고면 그날 자동매수 전체를 중지한다.

### 4.8 API 호출량 공유와 자동손절 우선
- 현재 S01 은 전용 속도 제한 없이 429 만 집계한다. 매수 엔진을 추가하면 같은 앱키의 호출 한도를 함께 쓴다.
- lease 보유 작업자가 소비하는 **공유 토큰 버킷**을 둔다 (초당·분당 상한은 키움 문서 확인 후 설정).
- 우선순위: ① S01 손절 시세·주문·취소·상태 ② 매수 체결 대조·취소 ③ 신규 매수 전송 ④ 보고용 조회.
  버킷이 부족하면 ③④ 를 다음 tick 으로 미룬다. 신규 매수는 cutoff 를 넘기면 포기한다 (추격 없음).
- tick 안에서 429 가 1회라도 발생하면 그 tick 의 신규 매수를 중단한다. N회 누적되면 그날 자동매수를 중지한다.

## 7. 전향적 SHADOW 검증과 불변 신호 축적
